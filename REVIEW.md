# REVIEW.md

## Code Review Findings for `app/main.py`

Every defect found during the review starter code is detailed below:

| #   | Where                  | What is wrong                                                                               | How you'd notice it                                                                                        | How you fixed it                                                                                                               |
| --- | ---------------------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 1   | `health()`             | Returns directly `{"status": "ok"}` without verifying MongoDB responsiveness.               | By going through the code                                                                                  | Implemented `db.command("ping")`. if ping fails or throws an exception, return HTTP 503.                                       |
| 2   | App initialization     | No indexes created at startup.                                                              | Since there are no indexes, duplicate entries can be made.                                                 | Added a `lifespan` handler that creates unique indexes on startup.                                                             |
| 3   | `create_employee`      | Check-insert race condition when creating employee.                                         | Two concurrent requests with the same `emp_code` both pass `find_one`.                                     | Created a unique index on `emp_code`, caught duplicates and raised HTTP 409.                                                   |
| 4   | `EmployeeIn`           | Missing validation that `shift_start != shift_end`.                                         | A request with `shift_start == shift_end` returns 201 instead of 422.                                      | Added `@model_validator` ensuring `shift_start != shift_end`.                                                                  |
| 5   | `create_employee`      | `created_at` set using naive `datetime.now()` and serialized as raw datetime.               | Client receives datetime string instead of the required epoch.                                             | Stored UTC BSON datetime in MongoDB; converted to epoch milliseconds integer (`int(dt.timestamp() * 1000)`) in API response.   |
| 6   | `list_employees`       | Offset by 1 bug `skip = page * page_size`. When `page = 1`, `skip = 20`.                    | When `?page=1`, it skips the first 20 employees completely, First page records are completely unreachable. | Corrected formula to `skip = (page - 1) * page_size`                                                                           |
| 7   | `list_employees`       | `total = db.employees.count_documents({})` counts entire collection ignoring query filters. | When filtering by department (`?department=Sales`), it` returns the total company wide headcount.          | Passed query filter `q` to `count_documents(q)`                                                                                |
| 8   | `list_employees`       | Missing sorting                                                                             | Results not ordered. contract requires ascending sort by `emp_code`.                                       | Added `.sort("emp_code", 1)` to the query.                                                                                     |
| 9   | `punch_in`             | Unhandled exception when `emp_code` does not exist                                          | Punching in with an invalid `emp_code` causes unhandled 500 instead of 404.                                | Verified employee existence: `if not emp: raise HTTPException(404, "Employee not found")`                                      |
| 10  | `punch_in`             | Race condition on punch in.                                                                 | Two concurrent punch in requests for the same employee and date both get inserted into the db.             | Enforced unique index. Caught `DuplicateKeyError` and returned HTTP 409.                                                       |
| 11  | `compute_late_minutes` | There is a bug in: `minutes = int(diff / 60); return minutes if minutes > 10 else 0`.       | At 09:40:01 (diff = 601s), `int(601/60) == 10`. `10 > 10` is False, it returns 0 instead of 10.            | First check the seconds if it is greater than 600 (10mins): `if diff_seconds > 600: return diff_seconds // 60 else: return 0`. |
| 12  | `compute_work_hours`   | Uses Python built-in `round()`.                                                             | Durations such as 4.495 round to 4 instead of 4.50.                                                        | Computed work hours using `Decimal(diff_seconds) / Decimal(3600)` with `ROUND_HALF_UP`.                                        |
| 13  | `attendance`           | Loads all documents into RAM and sorts via Python.                                          | High memory consumption and crashes on large datasets.                                                     | Pushed sorting to MongoDB.                                                                                                     |

## What was Examined and Decided NOT to be a Defect

1. **Absence of `id` Field in Attendance Documents**:
   - Observation: `punch-in` attempted to inject `doc["id"] = str(res.inserted_id)`.
   - Verdict: Removing `id` is intentional. The OpenAPI schema specifies attendance documents are addressed by `(emp_code, date)`. `_id` is internal and must never be exposed.
